1. SYSTEM OVERVIEW
================================================================================

JustReach is a mobile application that connects users with attorneys for legal
case management. The system has three main user roles:

- USERS: Submit legal cases, track case progress, chat with assigned attorneys
- ATTORNEYS: View assigned cases, communicate with clients via chat
- ADMINS: Manage attorney accounts, assign cases to attorneys, view statistics

7. AUTHENTICATION FLOW
================================================================================

USER/ATTORNEY REGISTRATION:
---------------------------
1. User fills signup form (mobile/src/app/auth/signup.js)
2. Frontend calls Firebase Authentication
   - Email/Password: doCreateUserWithEmailAndPassword()
   - Google: doSignInWithGoogle()
3. Firebase returns user object with UID and idToken
4. Frontend calls backend API: POST /auth/register
   - Sends: idToken, firstName, lastName, email, username
5. Backend verifies idToken with Firebase Admin SDK
6. Backend creates MongoDB record (User or Attorney)
7. For email signup: Verification email sent
8. For Google signup: Auto-verified
9. User logged out and redirected to login

LOGIN FLOW:
-----------
1. User enters credentials (mobile/src/app/auth/index.js)
2. Frontend calls Firebase Authentication
   - Email/Password: doSigninWithEmailAndPassword()
   - Google: doSignInWithGoogle()
3. Firebase returns authenticated user
4. Frontend calls backend: POST /auth/login
   - Sends: email
5. Backend checks MongoDB for user/attorney
6. Backend returns user data with role
7. Frontend routes based on role:
   - User → /user (User Dashboard)
   - Attorney → /attorney/dashboard (Attorney Dashboard)
   - Admin → /admin/dashboard (Admin Dashboard)
8. Auth context updated with user info

PROTECTED API CALLS:
--------------------
1. User makes API request
2. API client interceptor (mobile/src/api/apiClient.js):
   - Gets current Firebase user
   - Retrieves fresh idToken
   - Adds to Authorization header: "Bearer <token>"
3. Backend middleware verifies token
4. Request processed if valid

SCENARIO 1: USER SUBMITS A CASE
--------------------------------
1. Open User Dashboard: mobile/src/app/user/index.js

   - Show: server/controller/caseController.js → submitCase()

   - Case appears in "Track Case" page
   - Shows as "Pending" (no attorney assigned yet)

   - Click "Manage Cases"

   - Dropdown shows active attorneys

9. TROUBLESHOOTING & COMMON ISSUES
================================================================================

ISSUE: "Network Error" or "Connection Refused"
SOLUTION:
- Check if backend server is running: cd server && node server.js
- Verify mobile .env file has correct IP: EXPO_PUBLIC_API_BASE_URL=http://192.168.100.94:5000/api
- Ensure mobile and computer are on same WiFi network

ISSUE: "Firebase Auth Error" or "Google Sign-In Failed"
SOLUTION:
- Check Firebase config in mobile/src/firebaseApp/firebase.js
- Verify google-services.json exists in mobile/android/app/
- For APK builds, ensure SHA-1 certificate is registered in Firebase Console

ISSUE: "User Not Found" after Firebase login
SOLUTION:
- User exists in Firebase but not MongoDB
- Check backend registration endpoint
- Verify idToken is being sent correctly

ISSUE: Chat messages not appearing
SOLUTION:
- Check if case has assigned attorney (required for chat)
- Verify caseId is being passed to chat screen
- Check backend chat controller for errors

ISSUE: Cases not showing in Track Case
SOLUTION:
- Verify user is logged in (Firebase + Backend)
- Check API endpoint: GET /cases/user-cases
- Ensure apiClient has valid auth token

ISSUE: APK build fails
SOLUTION:
- Update EAS CLI: npm install -g eas-cli
- Verify Expo account: npx eas whoami
- Check eas.json build profiles
